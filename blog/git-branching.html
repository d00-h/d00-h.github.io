Main — 커밋 & 브랜치 기초

커밋 (Commit)

명령어설명
git commit현재 스테이징된 변경 사항을 저장소에 기록한다. 각 커밋은 고유한 해시값을 가지며 히스토리의 한 단위가 된다.
git commit -m "메시지"커밋 메시지를 인라인으로 작성하여 바로 커밋한다.
git commit --amend가장 최근 커밋을 수정한다. 메시지 변경이나 파일 추가 누락 시 사용한다.

브랜치 (Branch)

명령어설명
git branch <브랜치명>새 브랜치를 생성한다. 이동은 하지 않는다.
git checkout <브랜치명>해당 브랜치로 이동(HEAD를 옮김)한다.
git checkout -b <브랜치명>브랜치 생성과 동시에 이동한다. branch + checkout 단축형.
git switch <브랜치명>checkout의 현대적 대체 명령어. 브랜치 이동에 특화되어 있다.
git switch -c <브랜치명>브랜치 생성 + 이동. checkout -b와 동일하다.
git branch -d <브랜치명>병합이 완료된 브랜치를 삭제한다.
git branch -f <브랜치명> <위치>브랜치를 강제로 특정 커밋 위치로 이동시킨다.

브랜치 합치기 — Merge vs Rebase

Merge는 두 브랜치의 히스토리를 보존하며 병합 커밋을 만든다.
Rebase는 커밋을 다른 브랜치 위로 재배치하여 히스토리를 선형으로 만든다.
명령어설명
git merge <브랜치명>현재 브랜치에 지정한 브랜치를 병합한다. 병합 커밋이 생성된다.
git rebase <브랜치명>현재 브랜치의 커밋들을 지정한 브랜치 끝으로 재배치한다.
git rebase <A> <B>B 브랜치를 A 위로 rebase한다. 현재 브랜치를 바꾸지 않아도 된다.

Main — HEAD 이동 & 커밋 탐색

HEAD와 상대 참조

HEAD는 현재 작업 중인 위치를 가리키는 포인터다. 브랜치 이름 대신 커밋 해시나 상대 참조로 이동할 수 있다.

명령어 / 표현설명
HEAD^현재 커밋의 한 단계 위 부모 커밋을 가리킨다.
HEAD^^두 단계 위 부모를 가리킨다. ^를 여러 개 붙일 수 있다.
HEAD~<n>n단계 위 부모를 가리킨다. HEAD~3은 HEAD^^^와 동일하다.
git checkout HEAD^HEAD를 부모 커밋으로 이동시킨다(detached HEAD 상태).
git checkout <해시>특정 커밋 해시로 직접 이동한다.

커밋 되돌리기

명령어설명
git reset HEAD~1로컬에서 마지막 커밋을 취소한다. 변경 내용은 워킹 디렉토리에 남는다.
git revert HEAD해당 커밋의 반대 내용을 새 커밋으로 만들어 되돌린다. 원격 브랜치에서 안전하게 사용할 수 있다.
reset vs revert: reset은 히스토리를 지우므로 로컬 전용. revert는 새 커밋을 추가하므로 원격에 이미 push한 경우에 사용한다.
⚙️

Main — 고급 명령어

Cherry-pick

명령어설명
git cherry-pick <해시>특정 커밋 하나를 현재 브랜치에 복사해온다.
git cherry-pick <A> <B> <C>여러 커밋을 순서대로 복사해온다.

Interactive Rebase

명령어설명
git rebase -i HEAD~<n>최근 n개의 커밋을 대화형으로 재정렬·수정·삭제·합치기할 수 있다.

rebase -i 창에서 사용하는 주요 옵션:

  • pick — 커밋을 그대로 유지한다.
  • reword — 커밋 메시지를 수정한다.
  • squash — 이전 커밋과 합친다.
  • drop — 커밋을 삭제한다.

태그 (Tag)

명령어설명
git tag <태그명>현재 HEAD에 태그를 붙인다. 주로 버전 표시에 사용한다.
git tag <태그명> <해시>특정 커밋에 태그를 붙인다.
git describe <ref>가장 가까운 태그와의 거리를 <태그>-<커밋수>-g<해시> 형식으로 보여준다.

Remote — Push & Pull 기초

원격 저장소 클론 & 구조

명령어설명
git clone <url>원격 저장소를 로컬에 복제한다. origin 리모트가 자동 설정된다.
git remote -v등록된 원격 저장소 목록과 URL을 확인한다.

origin/main은 원격 저장소의 상태를 추적하는 리모트 트래킹 브랜치다. 직접 수정할 수 없고, fetch/pull 시 자동으로 업데이트된다.

Fetch / Pull / Push

명령어설명
git fetch원격 변경 사항을 로컬로 가져오되, 작업 브랜치에는 병합하지 않는다. origin/main만 업데이트된다.
git fetch origin <브랜치>특정 원격 브랜치만 가져온다.
git pullfetch + merge를 한 번에 수행한다.
git pull --rebasefetch + rebase를 한 번에 수행한다. 히스토리를 선형으로 유지할 때 사용한다.
git push로컬 커밋을 원격 저장소에 업로드한다.
git push origin <브랜치>특정 브랜치를 원격에 push한다.
git push origin <src>:<dst>로컬의 src 브랜치를 원격의 dst 브랜치로 push한다. 이름이 달라도 된다.
🚀

Remote — 고급 Remote 명령어

원격 트래킹 설정

명령어설명
git branch -u origin/<브랜치>현재 브랜치가 원격 브랜치를 추적하도록 설정한다.
git checkout -b <브랜치> origin/<브랜치>원격 브랜치를 추적하는 로컬 브랜치를 생성하고 이동한다.

Push / Fetch 심화

명령어설명
git push origin :<브랜치명>원격 브랜치를 삭제한다. (빈 src를 push하는 원리)
git fetch origin <src>:<dst>원격의 src를 로컬의 dst 브랜치로 가져온다.
git fetch origin :<브랜치명>로컬에 새 브랜치를 생성한다. (빈 src를 fetch하는 원리)
git pull origin <src>:<dst>fetch + merge를 지정한 브랜치 이름으로 수행한다.

충돌 해결 흐름

원격에 변경 사항이 있어 push가 거절될 때의 일반적인 해결 순서:
  • git fetch — 원격 변경 사항 가져오기
  • git rebase origin/main 또는 git merge origin/main — 로컬에 반영
  • 충돌 파일 수동 수정 후 git add
  • git rebase --continue 또는 git commit
  • git push

한눈에 보는 핵심 명령어 요약

명령어한 줄 요약
git commit변경 사항을 로컬 저장소에 기록
git branch / switch브랜치 생성 및 이동
git merge두 브랜치를 병합 (히스토리 보존)
git rebase커밋을 재배치하여 히스토리 선형화
git cherry-pick특정 커밋만 골라 복사
git rebase -i커밋 대화형 편집 (순서 변경·합치기·삭제)
git reset로컬 커밋 취소 (히스토리 변경)
git revert되돌리는 새 커밋 생성 (히스토리 보존)
git fetch원격 변경 사항 다운로드 (브랜치 병합 없음)
git pullfetch + merge 한 번에
git push로컬 커밋을 원격에 업로드
git tag특정 커밋에 영구 이름표 부착

느낀 점

처음 접해보는 Git이었는데, 게임 형식으로 배울 수 있어서 생각보다 재미있게 진행할 수 있었다. 메인 탭에서는 명령어를 하나씩 순서대로 배우는 구조여서 따라가기 수월했다.

원격 탭으로 넘어가면서부터는 확연히 복잡해졌다. 명령어를 어떻게 하면 더 짧고 효율적으로 쓸 수 있을지 고민을 많이 했고, 실제로 컴퓨터 두 대로 직접 push·pull을 해보면서 코드가 너무 길어지면 짧게 줄여보는 시도도 반복했다. 그 과정에서 짜증도 꽤 났지만, 그만큼 직접 부딪혀보며 익힌 것들이라 기억에 더 남는 것 같다.

한 번에 다 풀지 못해서 시간이 꽤 걸렸다. 코드가 완성된 이후에도 다시 처음부터 연습하면서 진도를 나갔는데, 그게 결과적으로는 더 도움이 됐다. 이번 계기로 시간 날 때마다 복습하면서 손에 익혀둘 것 같다.
