이 논문을 고른 이유

평소 자율주행차량의 보안에 관심이 있어 자율주행차 센서 로그 빅데이터 보안 플랫폼을 직접 설계한 적이 있다.

설계를 하면서 알게 된 것이 있었는데, 보통 자율주행차량의 데이터 파이프라인은 자율주행 센서 로그에서 생성된 데이터를 수집하는 단계를 거쳐 데이터 분석, 데이터 시각화로 넘어가는 흐름이다. 그런데 점차 여러 기술들을 통합하여 지능형 네트워크 차량으로 빠르게 발전하는 차량 산업으로 인해 광대한 범위의 사이버 위협 환경이 생길 수 있다는 걸 느꼈다. 그래서 데이터 수집 전에 사이버 해킹을 탐지할 수 있도록 실시간 탐지층을 추가한 데이터 파이프라인을 설계했다.

실시간 탐지층을 통해 차량 안에 거짓/위조 데이터가 들어오기 전, 1초 이내에 즉각 탐지하여 자율주행차량 환경을 혼란스럽지 않게 할 수 있다는 걸 확인할 수 있었다.

이건 데이터 측면에서 접근한 것이었는데, 그러다 보니 사이버보안 위험을 어떻게 사전에 분석하고 방어해야 하는지가 궁금해졌다. 기존에는 어떤 방식으로 차량 내부의 사이버보안을 분석했는지, 그리고 더 나은 방식으로는 어떤 것이 있는지 알고 싶어서 이 논문을 선택했다.

📌

문제 정의

연구 배경

현재 자동차 산업은 자율주행, OTA(Over-The-Air), V2X, ADAS 등 다양한 기술을 통합하며 지능형 네트워크 차량으로 빠르게 발전하고 있다. 하지만 이러한 발전은 차량 내부 네트워크와 ECU 간 연결 구조를 더욱 복잡하게 만들고 있으며, 결과적으로 사이버 공격 표면 또한 크게 증가시키고 있다.

이러한 공격 표면의 확대에 따라 TARA(위협 분석 및 위험 평가)는 자동차 사이버보안의 핵심 요소가 되었지만, 현재 대부분의 TARA는 여전히 수동으로 수행되고 있다. 따라서 분석 과정에 많은 시간과 인력이 필요하며, 차량 구조가 복잡해질수록 확장성이 떨어진다는 문제가 존재한다.

논문은 이러한 문제를 해결하기 위해 LLM 기반 자동화를 적용하면 함수 레벨 TARA를 효율적으로 수행할 수 있는지에 대해 다루고 있다.

기존 방식의 한계

기존 데이터로그 기반 접근 방식은 주로 차량 전체 레벨(vehicle-level)의 평가에 초점을 맞추고 있다. 하지만 ISO/SAE 21434에서 요구하는 것은 함수 레벨(function-level)의 세밀한 분석이며, 기존 방식은 이 부분에서 큰 한계를 가진다.

즉, 차량 전체 수준에서는 공격 흐름을 볼 수 있지만 실제 ECU, 통신 인터페이스, 소프트웨어 버전, 하드웨어 구성 등 컴포넌트 단위의 세밀한 위협 분석은 어렵다.

또한 기존 방식은 정적인 위협 라이브러리에 의존하기 때문에 새로운 공격 기법이나 새로운 기술이 등장할 때마다 사람이 직접 라이브러리를 업데이트해야 한다. 결과적으로 노동집약적이며 빠르게 변화하는 자동차 보안 환경에 적응하기 어렵다.

💡

핵심 아이디어

논문은 컴포넌트별 세부 정보와 LLM을 활용하여 함수 레벨 TARA를 자동화하는 시스템인 DefenseWeaver를 제안한다.

DefenseWeaver는 최소한의 수동 입력만으로 공격 트리 생성과 위험도 평가를 수행하여 보안 분석가의 업무 부담을 크게 줄인다. 또한 함수 레벨 단위의 세밀한 분석을 가능하게 하여 기존 방식보다 효율성, 정확성, 확장성을 향상시킨다.

  • OpenXSAM++ 기반 구조화 표현: LLM이 자동차 구성 정보를 효과적으로 해석할 수 있도록 하는 구조화된 기계 가독 형식
  • 멀티 에이전트 기반 LLM 프레임워크
  • LoRA 파인튜닝 및 RAG 기반 적응 구조
  • 공격 트리 자동 생성 및 위험도 평가: 4개의 자동차 프로젝트에서 11개의 실제 공격 경로 발견 및 패치 완료

특히 기존의 정적 위협 라이브러리 기반 방식과 달리, LLM이 차량 구성 정보를 기반으로 동적으로 공격 방법을 추론한다는 점이 가장 큰 특징이다.

🔧

방법론 / 시스템 설명

논문에서 제안한 전체 시스템은 DefenseWeaver이다. DefenseWeaver는 차량 내부 컴포넌트의 세부 정보를 기반으로 공격 방법을 동적으로 추론하고 위험 수준을 자동 평가한다.

전체 흐름

1. 자동차 시스템 입력 └── OpenXSAM++ 기반 구조 데이터 사용 (차량 기능, 구성 요소 정보 포함) 2. 기능 단위 분해 └── 시스템을 ECU, 센서, 통신 채널 등 기능별로 원자(atom) 단위로 나눔 3. 공격 시나리오 생성 └── LLM이 컴포넌트 세부 정보를 바탕으로 가능한 공격 방법 생성 4. Attack Tree 구성 └── 공격 경로를 트리 구조로 정리 (AND/OR 논리 관계로 연결) 5. 위험도 평가 └── 공격 가능성과 영향도를 기반으로 위험 점수 산출 (위험 수준 1~5)

1. 구성 표현 (OpenXSAM++)

기존 차량 시스템은 대부분 시각적 다이어그램 형태로 표현되기 때문에 자동 분석이 어렵다. 이를 해결하기 위해 논문은 자동차 시스템 구조를 OpenXSAM++이라는 구조화된 XML 기반 형식으로 변환하였다.

또한 모든 정보를 한 번에 LLM에 입력하면 정보량이 너무 많아 품질이 떨어질 수 있기 때문에, 원자 구조 표현(Atomic Structure Representation)을 사용한다. 시스템을 더 작은 단위의 원자(atom)로 분해하여 노드 간 관계를 유지하면서도 분석 가능한 수준으로 단순화한다.

2. LLM 기반 공격 방법 추론

DefenseWeaver는 하나의 AI가 모든 작업을 처리하는 것이 아니라, 역할을 나눈 멀티 에이전트 구조를 사용한다.

  • Sub-Tree Constructor: 개별 컴포넌트에 대한 공격 하위 트리 생성, 특정 공격 목표에 대한 가능한 공격 방법 분석
  • Attack Tree Assembler: 생성된 하위 트리를 하나의 전체 공격 트리로 조립, 공격 흐름 간 논리 관계를 연결
  • Risk Assessor: 공격 실현 가능성과 영향도를 평가, ISO/SAE 21434 기준 기반 위험 점수 계산

이를 통해 여러 AI가 생성, 조립, 평가 역할을 분담하여 보다 정교한 공격 분석을 수행한다.

3. 적응 전략 (LoRA + RAG)

DefenseWeaver는 진화하는 보안 위협에 대응하기 위해 LoRA 파인튜닝과 RAG를 활용한다.

  • LoRA: 자동차 보안 도메인에 맞게 LLM을 효율적으로 튜닝
  • RAG: 최신 보안 문서와 기업 지식을 검색하여 정확도를 향상

단순히 고정된 지식만 사용하는 것이 아니라, 새로운 공격 기법과 최신 보안 위협에도 적응 가능하도록 설계되었다.

전체적으로 보면 "자동차 보안 분석 파이프라인 자체를 AI 기반으로 자동화한 구조"라고 볼 수 있다.
📊

평가 및 결과 해석

논문은 DefenseWeaver를 실제 차량 프로젝트에 적용하여 검증하였다. 그 결과 총 11개의 실제 공격 경로를 발견하였으며, OEM 및 공급업체에 보고되어 실제 패치까지 진행되었다.

특히 기존 인간 전문가와 비교했을 때 다음과 같은 장점을 보였다.

  • 새로운 시스템 구성에 대한 높은 적응성
  • 비관습적인 공격 시나리오 탐지 가능
  • 차량 구성 차이에 따른 세밀한 공격 경로 분석 가능
  • 공격 트리 생성 시간 대폭 감소

모든 6개 시나리오에서 자동 생성 공격 트리의 평가 지표 점수가 더 높았으며, 특히 참신성이 105% 높다는 점이 인상적이다.

특히 차량 B 사례에서 UART 기반 공격 경로를 발견한 부분은 인간 전문가들이 놓쳤던 비정형 공격 벡터를 AI가 탐지했다는 점에서 의미가 크다고 느꼈다.

인간 전문가는 자신의 경험 밖에 있는 공격을 생각하기 어렵고, 비슷해 보이는 시나리오에서 세밀한 구성 차이를 놓치는 경향이 있었다. DefenseWeaver는 이 두 약점을 정확히 보완했다.

처리 시간

평가 차원에서 개인적으로 가장 중요하다고 생각하는 부분은 처리 시간이 98.8% 감소했다는 점이다. TARA는 차량 개발 주기 전반에 걸쳐 반복적으로 수행되어야 하는데, 수백 개의 컴포넌트를 가진 현대 차량을 분석하는 데 시간이 오래 걸린다면 분석 가능한 공격 경로의 범위가 좁아질 수밖에 없다. 실시간 대응이 생명인 자율주행차량 환경에서 분석 속도 자체가 달라진다는 것은 그 어떤 지표보다 실무적 의미가 크다.

참신성

참신성 지표가 2배 이상 높다는 것을 단순히 AI가 인간 전문가보다 창의적이라는 의미로 해석하기는 어렵다. 인간 전문가는 자신이 경험한 공격 패턴을 기반으로 시나리오를 구성하기 때문에, 경험 밖의 비정형 공격 벡터를 구조적으로 놓치기 쉽다. 반면 AI는 경험에 구애받지 않고 컴포넌트 간 관계를 기반으로 추론하기 때문에, 앞서 다룬 것처럼 인간 전문가들이 놓쳤던 UART 기반 공격 경로를 감지할 수 있었던 것이다.

실제 패치 완료

이 결과가 특히 중요한 이유는 실제 차량 프로젝트에 적용되었다는 점이다. 발견된 취약점이 패치까지 이어졌다는 것은 DefenseWeaver의 분석 결과가 바로 실무에 활용 가능한 수준임을 보여준다. 이는 LLM 기반 보안 자동화가 완전히 실현되기까지 얼마 남지 않았다는 사실을 가장 직접적으로 보여주는 근거이기도 하다.

⚠️

한계점

첫 번째, 아직 완전한 자동화가 아니라는 점이다. 공격 경로 생성과 위험 평가 자체는 자동화되었지만, 초기 위협 시나리오 정의는 여전히 사람이 직접 수행해야 한다. 즉 인간 전문가의 개입 없이 완전한 AI 기반 TARA라고 보기에는 아직 어려운 부분이 존재한다.

두 번째, 비용 문제이다. 실제 산업 환경에서 3개월 동안 약 3억 개의 토큰을 사용했다. 대규모 OEM 환경에서는 가능할 수 있지만, 소규모 공급업체 입장에서는 비용 부담이 상당할 수 있다.

세 번째, LLM 특성상 잘못된 추론(Hallucination) 가능성이 존재한다. 따라서 실제 산업 적용에서는 전문가 검증 과정이 여전히 중요할 것으로 보인다.

😀

느낀 점

자동차 보안 위험 분석인 TARA가 현재는 사람이 주도하고 인공지능이 보조하는 형태로 이루어지고 있어 100% 인공지능이 분석해주지는 않는다. 이 논문은 인공지능을 최대한 활용함으로써 사람이 할 수 있는 한계를 극복하고자 하는 시도를 보여준다.

다만 이 논문에서도 위험 시나리오를 설계하는 영역은 인간이 담당하고 있어, 완벽히 인공지능이 다 했다고는 볼 수 없는 점이 아쉽다.

그럼에도 굉장히 흥미로웠던 점은 실제 차량에서의 공격 경로를 발견하고 패치까지 진행해서 실무 적용 가능성이 높다는 점을 직접 보여준 것이다. 이론으로만 그친 것이 아니라 현대 차량에서 진짜 취약점을 찾아냈다는 점에서, 완전한 자동화까지 머지않았다는 느낌을 받을 수 있었다.

어떻게 보면 기존 방식의 반대 방향을 보여준 셈이다. 기존이 사람이 경험을 기반으로 라이브러리를 만들고 거기서 위협을 골라오는 방식이었다면, 이 논문은 컴포넌트 정보를 주면 LLM이 알아서 위협을 생성하는 방향으로 완전히 뒤집었다.

개인적으로 처음 자율주행차 보안 플랫폼을 설계할 때, 데이터 파이프라인에 실시간 탐지층을 추가하는 방식으로 외부 위협을 막는 데 초점을 맞췄다. 이 논문을 읽고 나서는 탐지 이전 단계, 즉 설계 단계에서 어떤 공격이 들어올 수 있는지를 미리 분석하는 것이 얼마나 중요한지를 더 실감하게 되었다. 두 접근이 서로 보완적인 관계라는 것도 느꼈다.

🚀

앞으로 해볼 것 / 확장 가능성

이 논문은 자동차 분야를 대상으로 하고 있지만, 실제로 논문 내부에서도 드론(UAV)과 선박 항법 시스템(ECDIS)에 적용 가능함을 보여주었다. 따라서 향후에는 다양한 사이버-물리 시스템(CPS)에도 확장 가능성이 크다고 생각한다.

  • 의료 분야: MRI, 환자 모니터링 시스템, IoT 의료기기 등이 서로 연결되어 있기 때문에 의료 데이터 유출이나 장비 오작동 위험을 사전에 분석할 수 있을 것이다.
  • 스마트시티 및 교통 시스템: 신호등, CCTV, 교통 관제 시스템 등의 연결 구조를 기반으로 대규모 보안 사고 가능성을 분석할 수 있다.

개인적으로는 이 논문의 구조를 자율주행 데이터 파이프라인 보안 연구와 결합해보고 싶다는 생각이 들었다. 기존에는 데이터 위조 탐지를 중심으로 접근했다면, 앞으로는 차량 내부 네트워크와 ECU 단위 공격 흐름까지 함께 분석하는 방향으로 확장하면 더 강력한 자율주행 보안 시스템을 설계할 수 있을 것이라고 생각한다.

결과적으로 AI 기반 보안 자동화 기술은 앞으로 자동차뿐 아니라 다양한 산업 전반의 핵심 보안 기술로 발전할 가능성이 매우 크다고 느꼈다.
