이 논문을 고른 이유

평소 자율주행차량의 보안에 관심이 있어 자율주행차 센서 로그 빅데이터 보안 플랫폼을 직접 설계한 적이 있다.

설계를 하면서 알게 된 것이 있었는데, 보통 자율주행차량의 데이터 파이프라인은 자율주행 센서 로그에서 생성된 데이터를 수집하는 단계를 거쳐 데이터 분석, 데이터 시각화로 넘어가는 흐름이다. 그런데 점차 여러 기술들을 통합하여 지능형 네트워크 차량으로 빠르게 발전하는 차량 산업으로 인해 광대한 범위의 사이버 위협 환경이 생길 수 있다는 걸 느꼈다. 그래서 데이터 수집 전에 사이버 해킹을 탐지할 수 있도록 실시간 탐지층을 추가한 데이터 파이프라인을 설계했다.

실시간 탐지층을 통해 차량 안에 거짓/위조 데이터가 들어오기 전, 1초 이내에 즉각 탐지하여 자율주행차량 환경을 혼란스럽지 않게 할 수 있다는 걸 확인할 수 있었다.

이건 데이터 측면에서 접근한 것이었는데, 그러다 보니 사이버보안 위험을 어떻게 사전에 분석하고 방어해야 하는지가 궁금해졌다. 기존에는 어떤 방식으로 차량 내부의 사이버보안을 분석했는지, 그리고 더 나은 방식으로는 어떤 것이 있는지 알고 싶어서 이 논문을 선택했다.

📌

문제 정의

연구 배경

현재 자동차 산업은 자율주행, V2X, OTA 업데이트, ADAS 등 다양한 기술들을 통합하면서 지능형 네트워크 차량을 향해 빠르게 발전하고 있다. ECU의 수와 차량 내 네트워크의 복잡성도 증가하고 있어, 광대한 사이버 위협 환경이 형성될 가능성도 커졌다.

이러한 공격 표면의 확대에 대응하기 위해 TARA(위협 분석 및 위험 평가)가 자동차 사이버보안의 핵심 요소가 되었다. ISO/SAE 21434, WP29 R155e 같은 국제 규제는 차량 생애주기 전반에 걸친 TARA 수행을 OEM과 부품 공급업체에 의무화하고 있다.

문제는 현재 TARA가 여전히 수동으로 진행되고 있다는 점이다. 그렇다면 TARA를 LLM 모델을 이용해서 자동화하면 이 문제를 해결할 수 있을까? 이 논문이 다루는 핵심 질문이다.

기존 방식의 한계

기존 데이터로그 기반 접근 방식들(SAHARA, EVITA, MulVal, CarVal)은 세 가지 한계가 있다.

  • 차량 레벨에 머문다. 소프트웨어 버전 하나 차이로 공격 벡터가 완전히 달라지는데, 기존 방식은 이 차이를 잡아내지 못한다.
  • 컴포넌트별 위협 분석의 정밀함이 부족하다. 개별 ECU의 하드웨어 구성, 소프트웨어 버전, 통신 채널, 인터페이스 단위의 세밀한 분석을 커버하지 못한다.
  • 새로운 공격 표면에 적응하지 못한다. 새로운 기술이 도입될 때마다 라이브러리를 수동으로 업데이트해야 한다는 노동집약적인 문제가 있다.
💡

핵심 아이디어

저자들이 제안한 핵심 아이디어는 정적 위협 라이브러리 대신 LLM의 추론 능력을 위협 라이브러리로 활용하자는 것이다. 컴포넌트의 소프트웨어 버전, 하드웨어 구성, 통신 채널 정보를 입력으로 주면 LLM이 그에 맞는 공격 경로를 동적으로 생성한다. 이를 구현한 시스템이 DefenseWeaver다.

  • OpenXSAM++: LLM이 자동차 구성 정보를 효과적으로 해석할 수 있도록 하는 구조화된 기계 가독 형식
  • 멀티 에이전트 LLM 프레임워크: TARA를 자동화하는 설계로, 적응성과 견고성을 위해 LoRA 및 RAG로 강화
  • 실제 검증: 4개의 자동차 프로젝트에서 11개의 실제 공격 경로 발견 및 패치 완료
🔧

방법론 / 시스템 설명

전체 흐름

1. 자동차 시스템 입력 └── OpenXSAM++ 기반 구조 데이터 사용 (차량 기능, 구성 요소 정보 포함) 2. 기능 단위 분해 └── 시스템을 ECU, 센서, 통신 채널 등 기능별로 원자(atom) 단위로 나눔 3. 공격 시나리오 생성 └── LLM이 컴포넌트 세부 정보를 바탕으로 가능한 공격 방법 생성 4. Attack Tree 구성 └── 공격 경로를 트리 구조로 정리 (AND/OR 논리 관계로 연결) 5. 위험도 평가 └── 공격 가능성과 영향도를 기반으로 위험 점수 산출 (위험 수준 1~5)

① 구성 표현: OpenXSAM++

시각적 다이어그램을 LLM 기반으로 OpenXSAM++ 형식으로 변환한다. 추출된 논리 경로를 LLM에 직접 공급하면 너무 많은 정보로 품질이 떨어지기 때문에, 각 논리 경로를 노드 간의 관계를 유지하면서 더 작고 관리 가능한 원자(atom) 단위로 분해해서 표현한다.

② LLM 기반 공격 방법 추론: 멀티 에이전트

세 개의 전문화된 에이전트가 분업한다. 여러 인공지능이 역할을 분담하는 구조다.

  • Sub-Tree Constructor: 공격 표면 파악 → 로컬 목표 설정 → 공격 방법 생성 순서로 하위 트리 생성
  • Attack Tree Assembler: 하위 트리들을 통합하여 완전한 공격 트리를 구성, 논리 일관성 검증
  • Risk Assessor: ISO/SAE 21434의 5가지 차원으로 공격 실현 가능성 평가, 안전/금전/운영/프라이버시 관점에서 영향도 산정

③ 파인튜닝 및 RAG를 통한 적응

  • Sub-Tree Constructor → LoRA 파인튜닝: 자동차 보안 도메인에 맞게 효율적으로 튜닝. 116개의 전문가 큐레이션 TARA 보고서로 학습
  • Risk Assessor → RAG: 실시간으로 최신 기업 가이드라인과 유사 사례를 검색하여 점수 산정에 참조

이 둘을 나눈 이유가 흥미롭다. RAG를 Constructor에 적용하면 관련 없는 사례가 혼입되어 품질이 오히려 떨어진다는 걸 실험적으로 확인했기 때문이다.

전체적으로 보면 "자동차 보안 분석 파이프라인을 AI로 자동화한 구조"라고 볼 수 있다.

평가 및 결과 해석

실차 4대에서의 침투 테스트

차량 A/B (BCM): 같은 IVI→게이트웨이→BCM 논리 경로지만 공격 방법이 완전히 달랐다.

  • 차량 A: OpenSSL 1.1.0a → CVE-2016-6309 버퍼 오버플로우 악용 → BCM 펌웨어 재프로그래밍 위험 수준 3
  • 차량 B: UART 디버그 인터페이스 노출 → Linux 6.1 CVE-2023-0179 권한 상승 → BCM 펌웨어 재프로그래밍 위험 수준 4

정적 라이브러리 기반 도구였다면 두 차량을 동일하게 취급했을 것이다. DefenseWeaver는 구성 차이를 정확히 반영해 서로 다른 공격 경로를 도출했다.

차량 C (CDC/OTA): TBOX 하드코딩 CA 인증서 발견 → MITM으로 OTA 펌웨어에 악성 코드 주입. 해시 검증 실패해도 업그레이드 진행하는 논리적 결함 확인 위험 수준 4

차량 D (PKES/UWB): UWB가 중계 공격을 막기 위해 도입되었지만, UWB 레인징 방해 + BLE 중계 조합으로 우회 성공. UWB 자체가 새로운 공격 표면이 된 역설적인 사례 위험 수준 5

총 11개의 공격 경로가 PoC로 검증되었고, 모두 해당 OEM/공급업체에 책임 있게 공개하여 패치 완료되었다.

⚠️

한계점

  • 위협 시나리오는 여전히 사람이 정의한다. 진입점과 끝점 설정은 여전히 인간의 몫이다. STRIDE 프레임워크와 통합하는 방향을 제안했지만 아직 구현은 아니다.
  • LLM 비용과 확장성 문제. 3개월간 3억 토큰 소비. 소규모 부품 공급업체에게 이 비용 구조가 현실적인지는 별도 논의가 필요하다.
  • 소스 코드 비공개. 상용 플랫폼 탑재로 인해 전체 코드가 공개되지 않아 재현 가능성이 제한적이다.
  • 공격 트리의 형식적 정확성 보장이 없다. 논문 자체에서도 인정하듯, 공격 트리의 올바름을 수학적으로 검증하는 것은 아직 열린 문제다.
😀

느낀 점

자동차 보안 위험 분석인 TARA가 현재는 사람이 주도하고 인공지능이 보조하는 형태로 이루어지고 있어 100% 인공지능이 분석해주지는 않는다. 이 논문은 인공지능을 최대한 활용함으로써 사람이 할 수 있는 한계를 극복하고자 하는 시도를 보여준다.

다만 위험 시나리오를 설계하는 영역은 인간이 담당하고 있어, 완벽히 인공지능이 다 했다고는 볼 수 없는 점이 아쉽다. 그럼에도 굉장히 흥미로웠던 점은 실제 차량에서의 공격 경로를 발견하고 패치까지 진행해서 실무 적용 가능성이 높다는 점을 직접 보여준 것이다. 이론으로만 그친 것이 아니라 현대 차량에서 진짜 취약점을 찾아냈다는 점에서, 완전한 자동화까지 머지않았다는 느낌을 받을 수 있었다.

어떻게 보면 기존 방식의 반대 방향을 보여준 셈이다. 기존이 사람이 경험을 기반으로 라이브러리를 만들고 거기서 위협을 골라오는 방식이었다면, 이 논문은 컴포넌트 정보를 주면 LLM이 알아서 위협을 생성하는 방향으로 완전히 뒤집었다.

개인적으로 처음 자율주행차 보안 플랫폼을 설계할 때, 데이터 파이프라인에 실시간 탐지층을 추가하는 방식으로 외부 위협을 막는 데 초점을 맞췄다. 이 논문을 읽고 나서는 탐지 이전 단계, 즉 설계 단계에서 어떤 공격이 들어올 수 있는지를 미리 분석하는 것이 얼마나 중요한지를 더 실감하게 되었다. 두 접근이 서로 보완적인 관계라는 것도 느꼈다.

  • SoK: Rethinking Sensor Spoofing Attacks Against Robotic Vehicles (EuroS&P 2023): DefenseWeaver의 UAV 사례에서 참조한 논문으로, 자율주행 센서 공격을 체계적으로 분류한 연구다.

다른 분야에 적용할 가능성

이 논문에서도 드론(UAV)과 선박 항법 시스템에 적용했으므로, 더 나아가 의료기기와 교통 시스템에서도 적용할 수 있다고 생각한다. MRI, 환자 모니터링 시스템, IoT 의료기기 등이 서로 연결되어 있어 의료 데이터 유출이나 장비 오작동 가능성을 사전에 분석하는 데 활용 가능하고, 교통 시스템도 신호등·CCTV 등 도시 인프라와 연결되어 있어 대규모 보안 사고를 예방할 수 있을 것이다.

연구/프로젝트로 발전시킨다면

내가 설계했던 자율주행차 센서 로그 보안 플랫폼은 데이터가 들어오기 전에 실시간으로 탐지하는 구조였다. 이 논문을 읽고 나서 한 가지 아이디어가 생겼다.

DefenseWeaver가 생성한 공격 트리를 CAN 버스 IDS(침입 탐지 시스템) 탐지 룰셋으로 자동 변환하는 파이프라인을 구현해보고 싶다. 공격 트리의 각 리프 노드에서 네트워크 레벨의 특징을 추출하고, 이를 탐지 룰로 변환하면 TARA(공격 분석) → IDS 룰(실시간 탐지)의 파이프라인이 자동화된다. 설계 단계의 보안 분석과 운영 단계의 실시간 탐지가 자연스럽게 연결되는 구조다.

결과적으로 인공지능 기반 보안 자동화 기술이 앞으로 자동차뿐 아니라 다양한 산업 전반의 핵심 보안 기술로 발전할 수 있음을 이번 논문을 통해 다시 한번 실감했다.
